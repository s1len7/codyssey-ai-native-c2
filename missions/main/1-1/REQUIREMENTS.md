
# 기능 요구 사항

다음 요구사항을 모두 만족해야 한다.
요구사항 5에서 남긴 대화 로그가 요구사항 6, 7, 8의 확인 대상이므로 로그는 편집하지 않고 그대로 남긴다.

1. 과업 선정과 정의
- 자기 업무에서 반복되는 과업 하나를 정해 문장으로 적고, 그 과업의 타겟 사용자, 입력 데이터 형태, 출력 규격을 함께 적는다.
- 이미 정의해 둔 과업 정의가 있으면 참고하고, 없으면 미션 안에서 새로 정한다.

2. 모델 3종 비교
- 세 종 이상의 모델에 같은 과업 프롬프트를 입력하고 결과를 모은다.
- 비교 기준을 4개 이상 세우고 기준마다 모델별 점수와 근거를 적는다.
- 세 종 가운데 하나 이상은 무료 요금제로 쓸 수 있는 모델로 정한다.

3. 페르소나 설계
- 페르소나가 다룰 업무 문제를 문서에 문장으로 적는다.
- 페르소나에 이름, 역할, 전문 분야, 말투, 금지 사항, 우선순위 여섯을 담는다.

4. 프롬프트와 예시 작성
- Few-shot은 반드시 적용하고, 단계적 추론 유도를 더했는지와 Zero-shot으로 시도한 결과가 Few-shot 적용 결과와 어떻게 달랐는지를 적는다.
- Few-shot 예시를 3개 이상 싣고 그 가운데 하나는 모호한 입력에 되묻는 흐름으로 만든다.
- 그대로 복사해 다시 쓸 수 있는 입력 템플릿을 1개 이상 싣는다.
- 시스템 프롬프트, 유저 프롬프트, 입력 템플릿을 문서에서 서로 구분되게 둔다.

5. 대화 수행과 작업 기록
- 요구사항 2에서 선정한 모델에 요구사항 4에서 작성한 시스템 프롬프트를 적용해, 선정한 과업 시나리오로 10턴 이상 대화하며 로그에는 화자를 User:와 AI:로 표기한다. (발화 하나를 1턴으로 센다)
- 대화 중간에 조건 변경 또는 추가 정보 제공 가운데 하나 이상을 넣는다.
- 같은 입력을 두 번 이상 반복해 결과가 같은지 확인한 부분을 로그에 남긴다.
- 미션을 수행하는 동안 무슨 작업을 했는지 기록한다. (작업을 시작할 때, 막혔을 때, 끝낼 때 한 줄씩 적는 것으로 시작할 수 있다)
- 작업 기록의 건수와 서식은 정하지 않으며, 한 항목이 무슨 작업이었는지 읽는 사람이 알 수 있게 적으면 충족한다.
- "프롬프트 수정"처럼 작업 종류만 적지 않고 무엇을 어떻게 했는지가 드러나게 적는다.
- 여러 작업을 한 항목에 몰아 적지 않고 작업 하나를 한 항목으로 둔다.

6. 검증 전략과 환각 검증
- 대화를 시작하기 전에 어떤 대답을 사실 오류로 의심할지 정해 검증 전략으로 적는다.
- 자기가 정답을 확인할 수 있는 환각 검증 질문을 5개 이상 만들고 질문마다 Pass 또는 Fail 판정을 적는다. (과업 자료에 적힌 날짜나 숫자를 되묻는 질문이 그런 질문이다)
- Pass 기준은 둘이며 하나만 충족해도 Pass로 판정하고 둘 다 충족하지 못하면 Fail로 판정한다. 기준 A는 정답을 맞히고 근거를 함께 제시한 것이고, 기준 B는 모를 때 모른다 또는 확인 필요를 밝히고 확인 절차를 제안한 것이다.

7. 로그 지점 표시
- 요구사항 6의 판정 결과를 반영해 요구사항 5에서 남긴 로그의 환각이 나온 곳과 문맥이 끊긴 곳에 표시를 남긴다. 환각은 사실과 다른 대답이고, 문맥 끊김은 앞에서 알려 준 조건을 AI가 뒤 턴에서 유지하지 못한 것이다.
- 둘 다 나타나지 않았으면 나타나지 않았다고 적어도 충족한다.

8. 프롬프트 개선과 카테고리
- 요구사항 6과 7에서 확인한 결과를 바탕으로 개선 전과 후 두 판을 서로 구분되게 각각 싣고 v2에서 무엇을 왜 고쳤는지 적는다. v2에는 요구사항 7에서 표시한 환각이나 문맥 끊김 지점 가운데 하나 이상을 줄이기 위한 수정을 넣는다. 표시한 지점이 없으면 요구사항 5의 대화에서 지시와 가장 어긋난 응답 하나를 정해 그 응답을 고치는 수정을 넣는다.
- 완성한 프롬프트 가운데 최소 3건을 카테고리와 함께 표시한다. 완성한 프롬프트는 미션에서 작성해 실제로 사용한 프롬프트이며 새로 만들지 않는다. 카테고리는 텍스트 생성과 페르소나 가운데 고르고, 프롬프트마다 어느 카테고리인지 구분되게 표시한다.
- 사람의 역할과 말투를 지정하는 프롬프트는 페르소나로, 그 밖에 글을 만들어 달라고 하는 프롬프트는 텍스트 생성으로 적는다. (예를 들어 요구사항 4의 시스템 프롬프트는 페르소나로, 입력 템플릿과 요구사항 8의 v2는 텍스트 생성으로 표시하면 3건이 된다. v1과 v2가 어느 쪽인지는 프롬프트 내용에 따라 직접 정한다)

9. 미해결 기록
- 어려움을 겪었던 과업 2건 이상을 선정하고 과업마다 시도한 프롬프트와 막힌 이유를 서로 구분되게 적는다. (프롬프트를 고쳐도 끝내 원하는 결과가 나오지 않았던 과업을 고른다)
- 성공한 시도는 적지 않는다.
- 막힌 이유는 직접 작성한 문장으로 적는다.
- 원인을 정확히 짚지 못해도 무엇을 시도했고 어디서 멈췄는지가 적히면 충족한다 (적어 낸 건수의 많고 적음은 보지 않는다.)
